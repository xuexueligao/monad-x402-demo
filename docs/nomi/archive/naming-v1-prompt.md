关键架构：
- Next App Router 提供页面与 API，业务逻辑放 src/server/nomi。
- SQLite 保存在 .local/nomi.db，持久化订单、付款尝试、工具任务、预算预留、订单事件和会话。
- 普通内存状态不能作为付款幂等、预算和订单的唯一依据。
- 一个 Node 常驻 worker 请求受 token 保护的内部 tick；每次处理一个任务并等待完成，关闭浏览器仍可推进。
- 使用单实例本地常驻服务。不要假定 SQLite 文件在无持久磁盘的托管平台会保留。
- 浏览器组件不能导入私钥或模型 key。服务端秘密不使用 NEXT_PUBLIC_，日志和证据不记录秘密、完整授权或用户未公开的描述。

支付生命周期必须先处理清楚：
已安装 withX402 的默认 authorization 流程会先执行 handler，再结算。
因此顾客付费 handler 只接受委托，不在里面支付工具或运行模型。
付款尝试在结算前持久化；onAfterSettle 记录结算结果；服务端核验链上成功回执和正确 Transfer 后，才进入 queued。
onAfterSettle 写数据库失败不会回滚链上转账，需要预写尝试与对账恢复。
不要把浏览器传来的 transaction 或 success 直接作为到账证明。
绑定 network + asset + payer + nonce 到订单，并用 network + txHash + logIndex 防止同一转账认领多单。验证会话、订单、预期 payer、收款方、金额和签名。普通订单 ID 不天然受代币转账授权保护。
如要使用 x402 扩展，先读当前包类型及官方资料，不能凭空假定扩展自动替你处理业务幂等。

两笔支付：

2. worker 使用猫专用测试钱包支付工具店 20000 最小单位。

预算：
每单只允许一个付费工具任务，单次 0.02 测试 USDC；每天 0.20 测试 USDC 工具预算、最多 10 个新订单；模型每单最多 2 次、每日最多 20 次。
同时只执行 1 单，排队上限 3 单。
报价前原子预留容量与预计工具预算，报价有效期 10 分钟；提交付款后保留到付款状态解决；收款后转为已承诺履约的预留。worker 领取既有预留，不再重复占用一份。
当日已消费 + 所有仍有效的未消费预留不得超过当日额度。跨日不清空未决预留，转换为消费时归入实际消费日。
金额使用最小单位字符串与 BigInt。预算检查和预留、消费转换放在数据库事务内。
报价、付款入口与 worker 都要执行相应校验，不能只依赖禁用按钮。

状态：
awaiting_payment、payment_pending、queued、working、reconciling、delivered、refund_pending、refunded、cancelled。
支付尝试单独记录 prepared、submitted、confirmed、unknown、failed。
签名已生成不等于已收款；交易哈希存在不等于成功。
付款状态不明时查询原尝试和 nonce，不能自动产生新授权。只有核验到明确失败，或原授权过期且未使用时，才能允许新尝试。
worker 租约过期不等于支付失败，恢复时先对账。
关闭营业不丢弃已收款订单。完成事件唯一，刷新不能重复增加成长或播放多个奖励。
