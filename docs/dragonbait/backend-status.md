## 已实现

- `contracts/src/UnrestrictedVault.sol`：独立保管原生 MON，Agent 可向任意有效地址付款，作为弱业务授权基线。
- `contracts/src/PolicyVault.sol`：独立保管原生 MON，检查白名单、单笔及固定周期累计额度；主人可明确批准一条被拒绝的请求。
- `contracts/src/NativeVault.sol`：共有请求格式、摘要、去重、资金入账、角色分离、两步主人交接、暂停和重入保护。
- `contracts/lib/payments.mjs`：统一付款工具、参数校验、同钱包串行发送、从实际回执判断 paid/blocked/reverted。
- `contracts/lib/events.mjs`：按区块恢复事件和原始统计，主人批准金额与 Agent 普通付款分开计算。
- `contracts/scripts/deploy-testnet.mjs`：Monad 测试网部署、逐笔保留哈希和进度，默认不入金。
- `contracts/scripts/verify-deployment.mjs`：只读核验链、编译运行时代码、角色、不可变参数和策略漂移。
- `contracts/scripts/demo.mjs`：可重复的固定意图链上对比实验。

完整接口、运行命令、角色边界和后续接入说明见 [合约 README](../../contracts/README.md)。

## 已保存的演示证据

两个金库初始余额各 0.1 本地 MON；白名单单笔上限 0.01、固定周期预算 0.02。

| 步骤 | 实际结果 | 对应金库余额 |
| --- | --- | --- |
| 向非白名单攻击者请求 0.03，普通钱袋 | Paid | 0.1 → 0.07 |
| 同一请求，策略金库 | Blocked：非白名单 | 0.1 → 0.1 |
| 白名单请求 0.011 | Blocked：单笔超限 | 0.1 → 0.1 |
| 合法请求 0.01 | Paid | 0.1 → 0.09 |
| 再合法请求 0.01 | Paid | 0.09 → 0.08 |
| 预算耗尽后再请求 1 wei | Blocked：周期预算耗尽 | 0.08 → 0.08 |
| 主人对第二步原请求独立批准一次 | Owner-approved paid | 0.08 → 0.05 |

策略金库最后累计 5 个 Agent 请求、3 次历史拒绝、3 次付款，其中 1 次来自主人批准。付款 0.05 中，0.02 是规则允许的付款、0.03 是主人明确批准，不能将后者描述成攻击绕过了防火墙。

这份演示明确标注未调用真实模型、请求来自固定意图样本。它证明相同付款意图会被不同权限架构处理，不能用来声称现场模型已被成功诱导。所有哈希属于本地 EVM，不能在 Monadscan 查询；本地耗时不等于 Monad 的确认时间。
